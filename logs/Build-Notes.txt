LoginServer
	1.
		Connection to the server is set up at boot
	2.
		When a login request is received from any world:
			->  It is placed in a queue
			->  The queue is handled in a separate worker
			->  The queue checks the correct login response to send
			->  Player files are stored in txt json files, so the worlds can parse those themselves
				-   We don't need to send them over the network

	Request Received
		->  Polled from the worker thread
		->  Sends back a response
			*   Already online
			*   Took too long
		->  The player file must be received from the network


Player Saving
	Master Server will hold all player files
		->  When the player is disconnected or logs out, the file is written to the master server
			->  The player file is unusable for 10 seconds to ensure successful write
			->  Login attempts will get the countdown message [21]
		->  When the player requests a packet from the master server, i.e. (pls send the rs2 server my friends list!)
			->  The server will find the player and send back the full list
		->  When the player attempts to log in
			->  We first check to make sure the player isn't already logged in
			->  Then we find a player by the username of the request
			->  If we cant find the player, we make a new one
			->  Then we will send the STRING of the player file over the network
			->  The rs2 server will receive it and parse it to json and the player will log in.
